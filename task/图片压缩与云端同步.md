# 图片压缩与云端同步

## 目标

将本地已验证的压缩图片同步到云端测试环境，降低小程序图片首屏和滚动加载流量；同时部署懒加载、静态缓存和 `wx.getWindowInfo` 兼容修复。不得修改数据库图片 URL。

## 前置条件

- 已读取 `AGENTS.md`、本文件和 `deploy/local/README.md`。
- 本地 Docker 后端、Caddy HTTPS、MySQL 已启动且健康。
- 已确认微信公众平台合法请求域名包含 `https://test.yunshecun.com`。
- 云端 TLS 证书已更新且有效；确认实际 Node 服务上传目录，文档默认是 `/home/project-2026/test/app/uploads/images`。
- 云端执行前备份上传目录和当前发布目录；不得执行 `db:seed`、删除卷或删除云端多余图片。

## 本地命令

```powershell
node deploy/local/压缩上传图片.js
docker compose -f deploy/local/docker-compose.yml -f deploy/local/docker-compose.optimized.yml up -d backend
cd code/backend
$env:LOCAL_TEST_BASE_URL = 'https://localhost:3443'
node --test --test-name-pattern "healthy HTTPS API|startup configuration|travel home advertisement" test/local-stack.test.js
```

压缩结果位于 `deploy/local/optimized-uploads/images`，清单为 `deploy/local/optimized-uploads/manifest.json`。当前参数：最长边 `1200px`、JPEG 质量 `80`；原图保留在 `code/backend/uploads/images`。

## 云端命令

在云端执行，先替换变量并确认目录：

```bash
set -Eeuo pipefail
BACKUP_DIR=/home/project-2026/deploy-backups/uploads-$(date +%Y%m%d-%H%M%S)
ACTIVE_UPLOAD_DIR=/home/project-2026/test/app/uploads/images
mkdir -p "$BACKUP_DIR"
cp -a "$ACTIVE_UPLOAD_DIR" "$BACKUP_DIR/images"
```

将本地 `deploy/local/optimized-uploads/images/` 中的文件上传到 `$ACTIVE_UPLOAD_DIR`，仅覆盖同名文件。然后按当前部署方式重建后端，使 `code/backend/src/app.js` 的缓存配置生效，并重载 Nginx。证书续期和 Nginx reload 必须使用已核验的云主机账号与路径，不得猜测证书文件。

例如在本地使用已核验的 SSH 账号上传：

```powershell
scp -r deploy/local/optimized-uploads/images/. <SSH_USER>@<SERVER>:/home/project-2026/test/app/uploads/images/
```

## 验收

- 访问 `https://test.yunshecun.com/api/health` 返回 HTTP 200。
- 首页广告接口返回的图片 URL 全部 HTTP 200、`Content-Type` 为图片类型。
- 代表性图片响应体积与 `manifest.json` 一致，最大图片不超过压缩清单值；静态响应包含 `max-age=2592000` 和 `immutable`。
- 微信开发者工具重新编译后，首页滚动无明显卡顿；支付下单请求不再因域名证书失败而 `timeout`。
- 验收失败立即停止切换，保留备份，不执行数据库回滚或 seed。

## 回滚

仅从 `$BACKUP_DIR/images` 恢复被覆盖的同名文件，重启后端并重新执行健康检查；不得删除云端新增文件、数据库记录或 Docker 卷。
